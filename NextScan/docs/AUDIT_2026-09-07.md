# NextScan Studio — audit and update plan

Date: 2026-09-07

## Scope and architecture

The active product is the C#/.NET Framework NextScan engine and Studio WinForms
application in `NextScan/`. Acquisition uses isolated x86/x64 TWAIN/WIA hosts,
named shared-memory frames and a parent broker. Network eSCL runs in managed
code. Core imaging uses RawImage; the GUI/export path still uses GDI+ in places.
The workspace also contains the legacy Photoshop helper, JSX bridges, Python
AI/document tools and local runtime assets outside the repository whitelist.
Those ancillary tools were inventoried, not comprehensively audited or rewritten.

Existing user modifications to TWAIN, contracts, build, status and the untracked
Studio application were retained. No commit, installation or real-device scan was
performed. Updated binaries are in `NextScan/bin`; the build also refreshes the
legacy helper's `NextScan.Engine.dll`.

## Verification

Run from `C:\PS_Fix`:

```powershell
.\NextScan\build.ps1 -NoWait
.\NextScan\bin\nsimgtest.exe
.\NextScan\tests\run_regressions.ps1
.\NextScan\tests\run_golden.ps1
.\NextScan\tests\run_escl.ps1 -NoWait
```

Build: all six targets compile. Imaging: 18 checks. Audit regressions: 13 checks.
TWAIN golden/behavior: 17 cases (without the optional ten-minute hang case).
eSCL: 11 checks including new chunked and absolute-Location cases.
Final suite results are recorded in the task response.

These checks do not establish that every bug has been found. Hardware scanning,
GUI gestures, Photoshop delivery, physical USB recovery and TLS trust behavior
need dedicated acceptance tests. Existing golden references were not regenerated.

## Next updates, in priority order

1. **Data integrity release.** Preserve 16-bit PNG/TIFF and ICC end-to-end: export
   still calls ToBitmap and reduces depth. Apply the same adjustment/crop pipeline
   to Save Session and Photoshop; currently session export takes filmstrip source
   images while Photoshop uses the displayed processed image. Add round-trip
   depth/profile tests and a visible original-versus-adjusted output choice.
2. **Reliable jobs and cancellation.** Add cancellable broker/network requests,
   bounded whole-job network deadlines, Windows Job Objects for cleanup after
   abrupt process death, per-device contention handling, session autosave and
   crash recovery. Preserve completed pages after cancellation or failure.
3. **Device acceptance matrix.** Test LiDE 400/ScanGear, WIA, actual network eSCL,
   ADF duplex, disconnect/reconnect, driver UI, scan-to-Photoshop and export.
   Add per-device certificate pinning and capability quirks based on measurements.
4. **Output workflow.** Searchable PDF with Bangla/English OCR, lossless PDF image
   options, batch naming/destination controls, explicit partial-export reporting,
   and selected/all-page export. Current native PDF is image-only JPEG output.
5. **Release engineering.** One-command CI, isolated dynamic-port simulator runs,
   installer/update/rollback, structured diagnostic bundles and localization.
   Package the currently untracked App sources deliberately when committing.
6. **Later product expansion.** WSD, film/ICC calibration and AI document cleanup
   after the integrity/reliability acceptance criteria pass.

A fully fixed/release-ready claim would be premature until the remaining data
integrity integration and hardware/GUI acceptance work above is complete.
